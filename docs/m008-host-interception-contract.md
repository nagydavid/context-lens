## OpenCode contract

- **Plugin shape.** A v2 plugin is a module whose **default export** is
  `{ id, setup(ctx) }` (`Plugin.define` from **`@opencode/plugin`**, the v2 package —
  *not* `@opencode-ai/plugin`, which is v1). ParaDoc hand-mirrors the context shapes with
  no SDK dependency; that stays valid.
- **Registration.** The config key is `plugins` (**plural**). Entries must be
  **directories**; OpenCode loads the directory's `index`/`server` module. A file path is
  skipped with `WARN message="configured plugin path must be a directory"`. The singular
  `plugin` key is v1 and is **silently ignored** in v2 — that is the silent state where MCP
  calls still work but native tool interception never runs.
- **Discovery.** Direct `.js`/`.ts` files are also discovered from `.opencode/plugins/`
  (project) and `~/.config/opencode/plugins/` (global). A `plugins/` directory beside a
  project-root `opencode.json(c)` is **not** discovered on its own.
- **Canonical seam (ONE seam only).** `ctx.tool.transform((editor) =>
  editor.update("read", (tool) => { const execute = tool.execute; tool.execute = async (args, options) => … }))`
  — the documented v2 Tools-domain way to modify a built-in tool (`ToolEditor.update(id, fn)`).
  `ctx.tool.hook("execute.after", …)` also fires on v2.1.0 but is absent from the plugin API
  reference; it must **not** be used together with `tool.transform` (double condensation).
- **Result shapes (both must be rewritten).** Under the transform seam the read result is a
  schema'd **page object** — `result.output = { content, truncated, next }` — *and* the
  model-facing text also lives in `result.content`, which may be a **string or an array** of
  parts. Rewrite `page.content`, set `page.truncated = false`, delete `page.next`, **and**
  rewrite `result.content` in whichever form it arrives. Changing only the structured
  `output` page leaves the full native read visible to the model.
- **Non-text pages pass through.** File/list pages have no condensable text; return them
  byte-identical rather than attempting a rewrite.
- **Prompt hook.** `ctx.session.hook("prompt", …)` is the v2 destination for `chat.message`
  (already used).
- **Logging.** `ctx.app.log` may be absent; the plugin falls back to
  `[paradoc] <level>: <message> {extra-json}` on stderr — the harness parser depends on this.

## Copilot contract

- **Extension entry.** `import { joinSession } from "@github/copilot-sdk/extension";
  await joinSession({ hooks, commands, tools })`. Project:
  `<git root>/.github/extensions/<name>/extension.mjs`; global:
  `~/.copilot/extensions/<name>/extension.mjs`. Both load paths observed
  (`Installed 1 native extension(s) for session …`, `loaded 1 extension(s) (mode=load_and_augment)`).
- **Interception hook.** `onPostToolUse` fires **only for successful tool results**
  (errors go to `onPostToolUseFailure`); return `{ modifiedResult }` (or `additionalContext`).
  Proven to replace the model-facing output.
- **Native read tool.** `view` with `view_range`. Directory listings are distinguishable via
  `toolTelemetry.properties.viewType === "directory"`. The model-facing field ParaDoc rewrites
  is `textResultForLlm`.
- **Gating.** Extensions require experimental mode (`settings.json` `"experimental": true`,
  or `--experimental` / `/experimental`). For project extensions in `-p` prompt mode the
  harness sets `GITHUB_COPILOT_PROMPT_MODE_EXTENSIONS=true`
  (log: `Loading project extensions in prompt mode`).
- **Slash commands are not dispatched in `-p` prompt mode** (documented in README; covered
  hermetically by `src/cli/acceptance.test.ts`).

## Recursion prevention

- **OpenCode.** `SessionSubagentRunner` reports each child session through
  `onSessionCreated(id)` → the `childSessions` Set in `src/opencode/hooks.ts`; both the read
  seam and the prompt hook return early for those session IDs. Under the transform wrapper
  the same guard applies because `options.sessionID` is passed into
  `hooks["tool.execute.after"]`. Child sessions are removed in `finally` (1 s cleanup cap) and
  tracking is capped at 256 IDs.
- **Copilot.** The child `copilot -p … -s --no-custom-instructions --disable-builtin-mcps
  --no-ask-user --available-tools=` process gets `PARADOC_CHILD=1` (hooks return early) and
  `GITHUB_COPILOT_PROMPT_MODE_EXTENSIONS` is **deleted** from its environment.
- **Policy (stated explicitly).** Host-spawned subagents (OpenCode `task`, Copilot
  subagents) are *not* in `childSessions`, so their reads **ARE intercepted**. That is a
  deliberate policy decision, not a bug; S02 keeps it and states it in code comments/tests.

## Decisions

Answers to the five open questions from S01 research, one rationale each:

1. **Canonical OpenCode seam = `ctx.tool.transform`** (`tools.update("read", …)`), one seam
   only. Rationale: it is the documented v2 Tools-domain API and is what the live, working
   installed runtime already uses; `tool.hook("execute.after")` is undocumented and pairing
   both double-condenses.
2. **OpenCode child model call: prefer `ctx.generate.text({ model, prompt })` when
   available** (generates without creating a session, invoking tools, or adding to session
   history → the recursion surface disappears), with the `ctx.session.create` +
   `childSessions` guard as the fallback when `generate.text` is absent. Rationale: fewer
   moving parts and no child-session lifecycle to leak. Note: `createV2Client` currently
   **drops** the v1 runner's `tools: {"*": false}` and `json_schema` format because v2
   `session.generate` accepts neither — child sessions today run **with tools** and
   unstructured output.
3. **Eligibility: bypass condensation only on `offset`** (OpenCode) and on Copilot
   `view_range` / `start_line` / `end_line`. A bare `limit` is how models ask for the top of
   a file, so it is **still condensed**. Rationale: `offset` is the unambiguous "I want a
   specific window" escape hatch; `limit` alone is the implicit full-read shape we are trying
   to condense. Applied to **both adapters and their tests together** (`src/opencode/hooks.ts`
   + `src/opencode/hooks.test.ts`, `src/copilot-cli/hooks.ts` `hasRangeArgument()`).
4. **Merge `milestone/M007` (`v0.2.2`) into the M008 branch first, as S02 task 1** — needed
   for the CI/release workflows (S03 installs a released package), `applyModel` controls, and
   `PARADOC_COPILOT_BIN`. Then port the two files that exist **only** as compiled JS in
   `~/.local/share/paradoc/dist` back into `src/`: `opencode/plugin-v2.js` (the
   `ctx.tool.transform` wrapper + page-shape rewriting) and `opencode/hooks.js` (the
   offset-only bypass), plus the `cli/install.js` registration fix.
5. **The installer must also repair the legacy singular-`plugin` state**: remove stale
   singular `plugin` entries and register the **plugins directory** (not the shim file), so
   existing users whose plugin sits under the silently-ignored v1 key start intercepting.

## Known risks

- **Free-model quota:** OpenCode free models return `Free usage limit reached`; every live
  OpenCode run must pin an authenticated model (`openai/gpt-5.6-terra`). The harness isolates
  `XDG_CONFIG_HOME`, so user-defined local providers are invisible to it.
- **Latency:** Copilot child spawns measured 8.3 s (this run) and up to ~20 s in research
  runs, versus the 45 s cap in `scripts/e2e-opencode.mjs` — S02/S03 assertions and timeouts
  must accommodate ~20 s per interception.
- **Experimental-mode dependency:** a fresh Copilot install without `"experimental": true`
  silently loads no extension, so interception never runs; fresh-install acceptance (S03)
  must set it explicitly.
